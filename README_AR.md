# Vitoria

[English](README.md) | [العربية](README_AR.md)

> منصة تجارة وإدارة متعددة الأدوار للقطاعين الزراعي والبيطري، تجمع اكتشاف المنتجات وعمليات الموردين والطلبات والإشراف والتحليلات وخدمات العملاء ضمن نظام واحد.

## نظرة عامة

Vitoria هي منصة أعمال متكاملة مبنية حول احتياجات التجارة الزراعية والبيطرية. تربط المستخدمين بالموردين، وتوفر في الوقت نفسه واجهات تشغيل مستقلة للإدارة والموظفين والجهات النقابية والموردين.

المشروع أوسع من متجر إلكتروني تقليدي؛ فالـBackend يحتوي على APIs منفصلة للتصفح العام، وعمليات المستخدمين المسجلين، وعمليات الموردين، ولوحات الجهات النقابية، وواجهات الموظفين، والإدارة.

## القدرات الأساسية

- كتالوج المنتجات ومقارنة المنتجات
- اكتشاف المنتجات الزراعية والبيطرية
- ملفات الموردين وعملياتهم
- سلة الشراء والكوبونات
- الدفع وإنشاء الطلبات
- إلغاء الطلبات وطلبات الإرجاع
- الفواتير
- المفضلة وتقييم المنتجات
- عناوين المستخدمين وطرق الشحن
- الإشعارات وتفضيلات الإشعارات
- التواصل وخدمة العملاء
- لوحات الجهات النقابية وخرائط الموردين والتقارير والتحليلات
- تحليلات المنتجات والطلبات والإرجاع لكل مورد
- Endpoints مدعومة بميزات AI للمنتجات الزراعية والبيطرية
- دعم الوظائف اللحظية عبر Laravel Reverb وLaravel Echo

## الأدوار وواجهات التشغيل

المستودع يفصل المسؤوليات بين عدة مجموعات Routes، منها:

- APIs عامة وموجهة للعملاء
- عمليات المستخدمين المسجلين
- APIs للموردين
- APIs للجهات النقابية
- APIs للموظفين
- APIs للإدارة

هذا التقسيم يعكس منصة تشغيل متعددة الأدوار وليس مجرد واجهة متجر واحدة.

## بنية الـAPI

```text
routes/
├── api.php             # العمليات العامة وعمليات العملاء
├── api_admin.php       # الإدارة
├── api_vendor.php      # الموردون
├── api_syndicate.php   # الجهات النقابية والتحليلات
├── api_employee.php    # الموظفون
└── web.php             # واجهة Inertia / Web
```

من القدرات الموجودة حالياً داخل الـAPI: تصفح المنتجات والمقارنة، السلة، الدفع، الطلبات، الإرجاع، الفواتير، الموردون، التحليلات، المفضلة، التقييمات، الإشعارات، واكتشاف المنتجات المدعوم بميزات AI.

## Real-time والأداء

المشروع يحتوي على Laravel Reverb وLaravel Echo للوظائف اللحظية، ويدعم Redis من خلال Predis، كما توجد آليات Throttling وCaching ضمن أجزاء من الـAPI.

راجع [Redis Setup](REDIS_SETUP.md) لملاحظات Redis الموجودة في المشروع.

## التطوير

إعداد المشروع يبدأ عادةً عبر:

```bash
composer install
cp .env.example .env
php artisan key:generate
npm install
```

بعدها يجب ضبط قاعدة البيانات وRedis والبريد والبث وأي خدمات أخرى من خلال `.env` حسب البيئة المحلية أو الإنتاجية.

> هذا التوثيق لا يدّعي أن كل الاختبارات أو الـbuild ناجحة حالياً. يجب التحقق من التشغيل والـmigrations والاختبارات والـbuild في البيئة المستهدفة.

## اختبار الـAPI

المستودع يحتوي على Postman Collection لاختبار واستكشاف الـAPI:

`SyriaZone.postman_collection.json`

تم الإبقاء على الاسم التاريخي للملف حتى لا يتم كسر أي workflow تطوير حالي.
